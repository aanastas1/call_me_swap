Да, такие проверки (if (values), if (context->a.elements), if (context->b.elements)) нужны и корректны: они предотвращают free(NULL).

Но важно: они не спасают, если указатель не равен NULL, но уже повреждён/освобождён/не принадлежит malloc. Именно поэтому у тебя и был SEGV в free() — в context->a.elements стоял “мусорный” адрес, и условие if (context->a.elements) сработало.

Что лучше сделать, чтобы free_all() стал надёжным:

    Перед любыми возможными ошибками обязательно обнуляй контекст так, чтобы a.elements и b.elements были NULL, пока ты не сделал stack_init.
        Самый простой вариант: ft_bzero(&context, sizeof(context)); в начале main (до parsing).

    После free ставь указатель в NULL, чтобы исключить double free при повторных вызовах:

c

if (values) { free(values); values = NULL; }
if (context->a.elements) { free(context->a.elements); context->a.elements = NULL; }
if (context->b.elements) { free(context->b.elements); context->b.elements = NULL; }

(Если хочешь, можно без локального values = NULL, но для context->* это важно.)

    И главное про ownership: values нельзя освобождать в free_all(), если values на самом деле не отдельный malloc-массив, который ты реально выделил, или если ты уже освободил его раньше. Самая безопасная схема:

    values выделяется parse_args()
    после setup_stacks() ты копируешь в context->a.elements
    сразу делаешь free(values); values = NULL;
    затем free_all(context, NULL) или free_all(context).
Лучше ничего не присваивать context->a.elements = values.

Почему:

    values у тебя int*
    context->a.elements — это массив t_element (с полями как минимум .value и .rank)
    даже если “по виду” указатель, память разного типа/размера, ты потом будешь читать/писать .rank/.value и получишь краши/порчу памяти.

Правильный вариант — как ты уже делаешь в setup_stacks:

    stack_init(&context->a, size) выделяет context->a.elements (массив t_element)
    compute_ranks() использует context->a.elements[i].rank
    цикл по i кладёт context->a.elements[i].value = values[i]

Тогда где освобождать values?

После того как ты скопировал values[i] в стек, можно освободить values, потому что в стеке уже лежат нужные данные.

То есть типовой порядок в main такой:

    values = parse_args(...);
    setup_stacks(&context, values, size);
    free(values); values = NULL;
    затем free_all(&context, NULL); (или сделай free_all вообще без параметра values)

Что лучше сделать с free_all()

Раз у тебя context->a.elements живёт отдельно (malloc в stack_init), а values — это временный массив от парсинга, самый надёжный дизайн:

    либо free_all(context) освобождает только a.elements и b.elements
    либо free_all(context, values) освобождает values, но тогда ты должен гарантировать: values освобождён только там, один раз (после setup_stacks ты ставишь values=NULL, если свободил раньше).

Если покажешь t_context / t_arr / t_element и как именно устроен parse_args() (возвращает новый int*? или иногда возвращает уже чей-то буфер?), я скажу, как именно лучше поправить free_all под твою ownership-схему.
Если ты делаешь
c

ft_bzero(context, sizeof(*context));

в начале context_init(), то это уже обнуляет вообще все поля структуры, включая op_counts. Поэтому строка
c

ft_bzero(context->op_counts, sizeof(context->op_counts));

после этого становится избыточной (ничего “переопределяет” по смыслу — просто повторное обнуление уже нулевых байт).

Правильно так:

    Оставь только одно обнуление — либо:
        общее в начале (ft_bzero(context, sizeof(*context));), и тогда op_counts больше не трогай;
    либо не делай общее, но тогда оставь ft_bzero(context->op_counts, ...) (и ещё другие нужные поля).

Рекомендация: оставь общее в начале, и удали второй ft_bzero — это избавит от путаницы и гарантирует, что все указатели типа a.elements / b.elements будут NULL, пока не выделишь память в stack_init().
