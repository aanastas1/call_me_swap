Брудфорс‑сортировка 5 чисел – перебор всех перестановок и выбор той, в которой элементы идут по возрастанию.

Шаги алгоритма
Сгенерировать все 
5
!
=
120
5!=120 перестановок массива из пяти чисел.
Для каждой перестановки проверить, является ли она отсортированной (каждый элемент ≤ следующего).
Первая найденная отсортированная перестановка – это результат сортировки.
Почему работает
Перебор всех перестановок гарантирует, что среди них будет ровно одна упорядоченная по возрастанию.
Проверка all(perm[i] <= perm[i+1] ...) за O(5) = O(1) для каждой перестановки, а всего перестановок 120, так что время работы ≈ 120 · O(1) = O(1) для фиксированного количества элементов.
Ограничения
Подходит только для очень маленьких массивов (пример – 5 элементов).
Для большего количества чисел количество перестановок растёт факториально, и брудфорс‑подход становится непрактичным.
Если нужно сортировать большие массивы, используйте стандартные алгоритмы – quick‑sort, merge‑sort и т.п.
Логика генерации 120 перестановок из 5 чисел на C без готовых функций

Подготовка
Создай массив a[5] со значениями, которые нужно переставлять.
Создай массив used[5] (логический) – показывает, какие элементы уже включены в текущую перестановку.
Создай массив perm[5] – будет хранить одну перестановку в процессе построения.
Рекурсивный подход (Backtracking)
Функция gen(pos) бирает элемент для позиции pos (от 0 до 4).
Если pos == 5 → все позиции заполнены, получена полная перестановка; вывести (или сохранить) массив perm.
Иначе:
Пройти цикл i = 0 … 4.
Если used[i] == false → элемент a[i] ещё не использован:
Помести его в текущую позицию: perm[pos] = a[i].
Отметь как использованный: used[i] = true.
Рекурсивно вызови gen(pos + 1).
После возврата сбрось пометку: used[i] = false (это «откат» шага).
Инициализация
Заполни used нулями.
Вызови gen(0) — начало построения с первой позиции.
Почему получаем ровно 120 перестановок
На первой позиции есть 5 вариантов, на второй – 4 оставшихся, затем 3, 2, 1.
Произведение 5·4·3·2·1 = 120, и рекурсия проходит каждый вариант ровно один раз.
Вывод/сохранение
Когда pos == 5, массив perm уже содержит одну из перестановок.
Можно просто printf каждый элемент в нужном формате, либо копировать в двумерный массив all[120][5]‑– для последующего использования.
Кратко: используем backtracking: выбираем элемент, отмечаем его использованным, переходим к следующей позиции,
после возврата откатываем отметку. Это гарантирует перебор всех возможных упорядочений без дублирования
и без необходимости хранить все комбинации заранее.
used[i] — это флаг, который говорит, использован ли i‑й элемент исходного массива a в той перестановке, которую мы сейчас собираем.

Как работает в процессе построения перестановки

Начало – все элементы ещё не выбраны, поэтому used[0] … used[4] равны false (0).
Выбор первого места (pos = 0)
Проходим по i = 0…4.
Если used[i] == false, значит элемент a[i] ещё не стоит ни в одной из уже заполненных позиций perm[0 … pos‑1].
Мы копируем его в perm[0] и ставим used[i] = true, объявляя, что этот элемент теперь «занят» в текущей перестановке.
Переходим к следующей позиции (pos = 1)
Снова перебираем все индексы i.
Теперь некоторые used[i] уже true (те, которые уже находятся в perm[0]). Их пропускаем, чтобы не использовать один и тот же элемент дважды.
Выбираем следующий свободный элемент, ставим used[i] = true и записываем его в perm[1].
Продолжаем пока не заполним все 5 позиций. Когда pos == 5 получаем полную перестановку, все used[i] уже true.
Откат (backtrack) – после вывода/сохранения этой перестановки возвращаемся на один уровень рекурсии: сбрасываем used[i] = false для последнего выбранного элемента, тем самым «освобождая» его для новых вариантов, и продолжаем цикл, выбирая другой элемент для той же позиции.
Итак, «элементы уже включены в текущую перестановку» — это те элементы массива a, которые уже скопированы в массив perm на какие‑то позиции и помечены в used как занятые, чтобы их нельзя было выбрать повторно в рамках той же перестановки.
Во время рекурсивного построения перестановки (Backtracking) функции gen(pos) нужно знать три состояния:

массив	назначение
a[5]	исходные элементы, из которых составляются перестановки
used[5]	логические флаги — какой элемент уже занял место в текущей частичной перестановке
perm[5]	текущая частично‑сформированная перестановка (на позициях 0 … pos‑1)
Как передавать их в рекурсию
Глобальные (статические) переменные – самый простой способ в C: объявить эти три массива вне любой функции и в gen() обращаться к ним напрямую. Тогда в сигнатуре функции передаёте только текущую позицию pos.
c


int a[5];          // исходные числа
int used[5];       // 0 – не использован, 1 – использован
int perm[5];       // формируемая перестановка
void gen(int pos) { … }
Параметры функции – если хотите избежать глобального состояния, передайте их как параметры. Поскольку массивы в C передаются как указатели, сигнатура будет:
c


void gen(int pos, int a[5], int used[5], int perm[5]);
При каждом рекурсивном вызове передаёте те же три массива (том же месте в памяти), изменяя только их содержимое — это и есть «текущий» статус перестановки.

Что происходит внутри gen
c


if (pos == 5) {
    // perm уже полностью заполнен → вывод/сохранение
    return;
}
for (int i = 0; i < 5; ++i) {
    if (!used[i]) {               // элемент ещё свободен
        perm[pos] = a[i];         // помещаем его в текущую позицию
        used[i] = 1;              // отмечаем как занятый
        gen(pos + 1, a, used, perm); // рекурсия для следующей позиции
        used[i] = 0;              // откат: «освобождаем» элемент
    }
}
Таким образом, да, в каждый вызов рекурсии передаются три массива (либо как глобалы, либо как параметры), а их содержимое меняется и откатывается, позволяя перебрать все

!
