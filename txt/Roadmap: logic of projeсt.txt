
Roadmap: логика проекта и “что из чего собирается”

    main / args

    Парсинг argv: собираем флаги (--simple/--medium/--complex/--adaptive, --bench) и список целых.
    Валидация: только int, без дублей, корректные форматы.
    Если чисел нет и нет параметров сортировки → ничего не печатаем, выходим.

    Модель данных (stack a/b) + операции

    Реализуем две стека a и b.
    Реализуем операции языка push_swap как функции: sa sb ss pa pb ra rb rr rra rrb rrr
    Каждая операция:
        реально меняет структуры стеков,
        печатает название операции в stdout с \n,
        инкрементит счетчики операций (для --bench).

    Дисордер (обязательный)

    Перед любыми ходами считаем disorder по текущему содержимому стека a (через пары).
    Значение преобразуем к % для отчёта в --bench.

    Нормализация значений (индексы/ранги)

    Для стратегий chunk/radix нужны ранги: заменяем каждое число на его позицию в отсортированном массиве (0..n-1).
    Это делается один раз до сортировки.

    Стратегии

    --simple / adaptive(low disorder): O(n²) стратегия (инсершн/селект по минимуму с двухстековой вставкой).
    --medium / adaptive(medium disorder): O(n√n) стратегия (chunk/range: разбиваем по рангу на блоки размера ~√n, перекладываем в b, потом возвращаем).
    --complex / adaptive(high disorder): O(n log n) стратегия (radix по битам от рангов с pb/ra и финальным pa).

    Сборка результата

    Каждая стратегия вызывает операции (через общий интерфейс op_*).
    В конце stack a отсортирован; stack b пуст.
    Если --bench включен: печатаем в stderr:
        disorder в процентах (2 знака),
        имя стратегии и её класс,
        total operations,
        количество каждого типа операции.

Прототипы (архитектура модулей на C)

    parse_args.c/h: разбор argv + валидация + массив int
    stack.c/h: двусвязный список/узлы + базовые функции
    ops.c/h: op_sa/op_sb/... (печать stdout + счетчики в `t_ctx
    disorder.c: double compute_disorder(t_stack *a)
    rank.c: int *make_ranks(int *values, int n) (сортировка копии + map)
    tiny_sort.c: оптимизации для n <= 3/5 (если захотите уменьшить операции)
    strategy_simple.c, strategy_medium.c, strategy_complex.c, strategy_adaptive.c
    bench.c: bench_dump(t_ctx*, disorder, strategy_name, complexity)

Ключевое: никаких global переменных — счетчики/контекст хранить в t_ctx и передавать по цепочке.
