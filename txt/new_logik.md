Push Swap с использованием массива с циклическим сдвигом индексов (Ring Buffer):

1. Основная концепция (Суть модели)
Вместо того чтобы двигать данные в памяти, мы двигаем указатель начала (start_index).

Стек — это фиксированный массив памяти.
Верх стека (Top) — это всегда элемент по индексу start_index.
Операции rotate (ra, rb) — это не сдвиг данных, а просто увеличение индекса start на 1 (по модулю размера массива).
Операции reverse rotate (rra, rrb) — это просто уменьшение индекса start на 1.
Операции push (pa, pb) — это перенос значения из одной ячейки массива в другую и изменение соответствующих start и size.
2. Логика операций
Rotate (ra, rb) — Сдвиг "вверх"
Что происходит: Элемент, который сейчас наверху, уходит на дно. Второй элемент становится верхним.
Логика индекса: start = (start + 1) % capacity.
Результат: Очередь элементов сдвигается влево. То, что было вторым, теперь первый по индексу.
Reverse Rotate (rra, rrb) — Сдвиг "вниз"
Что происходит: Элемент с самого дна перелетает наверх. Остальные сдвигаются вниз.
Логика индекса: start = (start - 1 + capacity) % capacity.
Результат: Очередь сдвигается вправо. То, что было последним (перед start в цикле), становится новым start.
Ключевое преимущество: В отличие от списка, здесь это мгновенная операция (просто арифметика), не требующая поиска предпоследнего элемента.
Swap (sa, sb) — Обмен
Что происходит: Меняются местами два верхних элемента.
Логика:
Определяем индекс первого: idx1 = start.
Определяем индекс второго: idx2 = (start + 1) % capacity.
Меняем значения в этих ячейках массива местами.
Важно: start и size не меняются.
Push (pa, pb) — Перенос
Самая сложная логика, так как меняется размер стека.

Передатчик (откуда берем):
Берем значение из arr[start].
Уменьшаем size на 1.
Сдвигаем start вперед: start = (start + 1) % capacity (как будто удалили верхний).
Приемник (куда кладем):
Увеличиваем size на 1.
Сдвигаем start назад: start = (start - 1 + capacity) % capacity (чтобы освободить ячейку перед текущим верхом).
Записываем значение в новую ячейку arr[start].
Итог: Элемент физически переместился из одной части памяти в другую, логически он теперь верхний в новом стеке.
3. Логика стратегий сортировки
Поиск элемента (для стратегии Simple)
Поскольку у нас нет указателей, поиск элемента с определенным рангом требует прохода по массиву.

Алгоритм:
Запускаем цикл от i = 0 до size - 1.
Вычисляем реальный индекс: real_idx = (start + i) % capacity.
Сравниваем arr[real_idx] с искомым рангом.
Если нашли, запоминаем i (это расстояние от верха).
Оптимизация хода:
Полученное i — это количество шагов ra.
Количество шагов rra = size - i.
Сравниваем i и size - i и выбираем меньшее. Это гарантирует минимальное число операций вращения.
Strategy Simple (Выбор минимума)
Пока в стеке A больше 3 элементов:
Найти минимальный ранг в A (проход по всем элементам).
Рассчитать дистанцию до него (через ra или rra).
Выполнить вращение, чтобы минимальный элемент оказался наверху.
Выполнить pb (перенести в B).
Оставшиеся 3 элемента отсортировать жесткой логикой (перебором вариантов).
Пока B не пуст: выполнить pa (вернуть элементы обратно в A, так как они там лежали в порядке возрастания, то при возврате они выстроятся в A тоже по возрастанию).
Strategy Medium (Чанки)
Разбить диапазон рангов на блоки (чанки) размером sqrt(N).
Итерироваться по блокам (от 0 до N).
Пока в стеке A есть элементы из текущего блока:
Если верхний элемент A относится к текущему блоку:
Если он "лучше" (меньше) текущего верха B, возможно, стоит повернуть B перед отправкой, чтобы сохранить порядок.
Выполнить pb.
Иначе: выполнить ra (пропустить этот элемент, он пока не в блоке).
Вернуть все из B в A.
Strategy Complex (Radix Sort)
Найти максимальный ранг и вычислить количество битов (maxbits).
Для каждого бита (от 0 до maxbits-1):
Проходить по всем элементам в A:
Если у ранга текущий бит равен 0: выполнить pb (отправить в B).
Если бит равен 1: выполнить ra (оставить в A).
Когда A пуст, вернуть все из B в A (выполнить pa пока B не пуст).
После прохода по всем битам массив будет полностью отсортирован.
4. Ключевые отличия от списка
Скорость вращения: В списке rra требует поиска предпоследнего элемента (O(n)). В массиве это просто арифметика (O(1)).
Память: Массив выделяется один раз. Нет накладных расходов на malloc для каждого узла и риска утечек.
Доступ: Доступ к любому элементу по индексу в цикле прост, но поиск конкретного ранга все равно требует линейного прохода (как и в списке).
Границы: Нужно всегда помнить про модульную арифметику (% capacity) при переходе через конец массива.
Эта логика полностью соответствует твоему roadmap, но оптимизирует выполнение операций за счет смены реализации структуры данных. Ты готов к реализации?

1. t_optype (Перечисление типов операций)
Это список всех возможных команд, которые может выполнять твоя программа.

Назначение: Используется как индекс для массива счетчиков операций (op_counts), чтобы статистика была структурированной.
Почему так: Вместо того чтобы писать if (cmd == "sa"), мы используем числа (0, 1, 2...), что быстрее и удобнее для массивов.
Значения:
OP_SA, OP_SB, OP_SS — операции обмена (swap).
OP_PA, OP_PB — операции переноса (push).
OP_RA, OP_RB, OP_RR — вращение по часовой (rotate).
OP_RRA, OP_RRB, OP_RRR — вращение против часовой (reverse rotate).
OP_COUNT — автоматическое число, равное общему количеству операций. Используется как размер массива счетчиков, чтобы не ошибиться с размером вручную.
2. t_stack (Структура стека на основе массива)
Это ядро твоей реализации. Она описывает один стек (либо a, либо b).

int *arr: Указатель на выделенный блок памяти (массив), где хранятся ранги (или значения) чисел. Это "склад" данных. Память выделяется один раз при инициализации.
int size: Текущее количество реальных элементов в стеке. Важно: это не размер выделенной памяти (capacity), а сколько элементов сейчас активно используется.
int capacity: Максимальный размер массива, который был выделен через malloc. Это лимит, за который нельзя выйти без перераспределения памяти (хотя для Push Swap можно сразу выделить под максимальное число аргументов).
int start: Самое важное поле. Это индекс в массиве arr, который указывает на верхний элемент (Top) стека.
Если start = 0, то верхний элемент лежит в arr[0].
Если start = 5, то верхний элемент лежит в arr[5].
При операции rotate (ra) мы просто делаем start++.
При операции reverse rotate (rra) мы делаем start-- (с учетом модуля capacity).
Это позволяет реализовать все вращающие операции за O(1) без копирования данных.
3. t_ctx (Контекст программы)
Это глобальное состояние, которое передается во все функции. Хранит всё, что нужно для работы программы.

t_stack a: Структура первого стека (исходный, который нужно отсортировать).
t_stack b: Структура второго стека (временный, для хранения элементов).
int bench_enabled: Флаг (0 или 1). Если включен (например, аргумент --bench), программа будет считать и выводить статистику. Если нет — просто молчит.
long op_total: Счетчик всех совершенных операций. Используется для проверки лимита (например, 700 операций для 100 элементов).
long op_counts[OP_COUNT]: Массив счетчиков для каждого типа операции отдельно.
op_counts[OP_SA] хранит количество выполненных sa.
op_counts[OP_PA] хранит количество pa.
Нужен для детального отчета в режиме бенчмарка (чтобы видеть, какие операции программа использует чаще всего).
Итог:

t_optype — это "алфавит" команд.
t_stack — это "коробка" с данными и указателем на верх.
t_ctx — это "диспетчерская", которая управляет двумя коробками и ведет статистику.

Флаги (параметры командной строки --simple, --medium и т.д.) нужно обрабатывать на этапе парсинга аргументов (parse_args), еще до создания стеков.

Почему это нужно делать?
Они не числа: Флаги --simple, --medium и т.д. — это строки. Твоя главная задача парсинга — собрать все аргументы в массив целых чисел (int *values).
Ошибка валидации: Если ты попробуешь передать строку "--simple" в функцию atoi (или свою ft_atoi), она вернет 0 (или ошибку).
Если вернет 0: ты добавишь лишнее число 0 в свой стек. Это испортит данные (теперь у тебя лишний элемент, которого не было в исходных числах).
Если вернет ошибку: твоя валидация (validate_ints) посчитает это за некорректное число и программа вылетит с ошибкой, хотя на самом деле пользователь просто указал режим работы.
Разделение логики: Флаги управляют поведением программы (какую функцию запустить), а числа — это данные для сортировки. Их нельзя смешивать в одном массиве.
