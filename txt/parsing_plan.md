План первой стадии: разбор входа
1) Определи состав аргументов

    argv[1..] может содержать:
        один из флагов: --simple, --medium, --complex, --adaptive
        или список чисел (как строки).
    Прими правило: если флаг есть — он один и находится в начале (обычно так проверяют). Если флагов больше/неизвестный флаг — ошибка.

2) Выбери стратегию (если был флаг)

    По значению флага выстави enum/константу стратегии.
    Если флага нет — стратегия adaptive.
    Сохрани выбранное значение, чтобы дальше можно было “в момент сортировки” выбрать алгоритм.

3) Распарсь числа (все остальные аргументы)

    Для каждого токена:
        убедись, что это корректное представление целого:
            допускаются +/-
            дальше должны быть только цифры
            не допускай пустую строку, пробелы внутри, мусорные символы
        проверь диапазон (чтобы int не переполнялся):
            аккуратно обработай через strtoll/аналог и проверь границы
    Если что-то не так — печатай Error\n в stderr и заверши.

4) Проверь дубликаты

    Как только получил все числа (или по ходу — быстрее):
        проверяй отсутствие одинаковых значений.
    При дубликате — Error\n в stderr и exit.

5) Создай структуры под стек a

    Переведи список чисел в структуру “стек a”.
    Учитывай правило ТЗ: “первый аргумент — верх стека”.
        значит при построении a делай так, чтобы a[0] соответствовал первому числу из argv.

6) Выход из parse

Функция/модуль парсинга должен дать результат:

    stack_a (готовый)
    size
    выбранная стратегия
    и сигнал “ошибка” (чтобы главный мог сделать единый Error\n)

Какая “первая функция” тут лучше всего

Обычно удобно как первую функцию проекта сделать что-то вроде:

    parse_input(argc, argv, &strategy, &stack_a) → bool/success или
    build_stack_and_strategy(argc, argv, ...).

Самое эффективное для push_swap на практике (и для твоего ТЗ с disorder/bench/выбором стратегии) — это такой компромисс:
Структуры данных

    Стек a/b — как двусвязные/односвязные списки (linked list)

    Храните top как head.
    Операции типа sa/sb/pa/pb — O(1) (работают с head и вторым элементом).
    ra/rb и rra/rrb обычно O(n) (прокрутка), но в оценке проекта важны именно число операций push_swap, а не время C-программы.

    Для вычислений “рангов/порядка” — отдельный массив при парсинге

    После разбора аргументов: сделайте массив значений, отсортируйте, сделайте coordinate compression (каждому числу присвойте ранг 0..n-1).
    В узлы linked list кладите не только исходное значение, но и rank/index (удобно для алгоритмов и для “сколько уже на месте”).
    Disorder можно считать либо:
        по списку (O(n²) и так по ТЗ), либо
        по массиву в исходном порядке (самый простой способ — сохранить исходный порядок при парсинге).

Архитектура по модулям

    parse.c: разбор флагов + валидация аргументов + сбор a + проверки на дубликаты.
    disorder.c: compute_disorder(stack_a_before_moves).
    strategy_select.c: выбор стратегии по флагу (--simple/--medium/--complex) или по disorder (--adaptive).
    sort_simple.c, sort_medium.c, sort_complex.c, sort_adaptive.c: генерация операций.
    operations.c: реализация sa/sb/ss/pa/pb/... и печать в stdout.
    bench.c: только учет/вывод метрик (в stderr).

Enum стратегий

    Enum типа STRAT_SIMPLE, STRAT_MEDIUM, STRAT_COMPLEX, STRAT_ADAPTIVE.
    Храните выбранную стратегию в main/контексте, дальше передавайте в функции (без глобальных переменных).

Обработка ошибок (самый удобный паттерн)

    Все функции парсинга возвращают int ok / bool ok.
    При любой ошибке (не int, переполнение, duplicate, некорректный флаг):
        освобождаете выделенную память (если нужно),
        в main печатаете один раз Error\n в stderr,
        выходите.
    Никаких “частичных” печатей операций до успешного парсинга.

Как сделать bench (чтобы не смешивать с логикой)

    В operations.c при выполнении каждой операции увеличайте счетчики (структура t_bench).
    В stdout печатайте только сами операции.
    В конце сортировки (если --bench/или флаг присутствует по ТЗ) печатайте метрики в stderr, включая disorder (% с 2 знаками), имя стратегии, теоретический класс и total count + breakdown.
