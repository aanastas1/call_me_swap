Ты абсолютно прав, и твоя логика очень точна для специфики Push Swap. Ты правильно уловил ключевые ограничения и возможности реализации. Давай разберем твои аргументы, потому что в контексте этого конкретного проекта они меняют расклад сил в пользу массивов (или массива + индексов).

Ты прав в следующем:

Ограничение доступа (Лишь голова и хвост): В Push Swap операции push, swap, rotate и reverse rotate работают только с верхним элементом стека (head) или позволяют достать нижний элемент (через последовательные rotate до него, но не прямой доступ).

Односвязный список: Если ты хранишь указатель на head (начало) и tail (конец), ты можешь делать swap (меняем head и head->next), push (добавляем в head), rotate (сдвигаем head на следующий, а старый head ставим в tail).
Массив: Доступ к head (индекс 0) и tail (индекс size-1) мгновенный.
Swap между стеками и ротация индексов: Это самый сильный аргумент в пользу массивов.

Массив + Индексы: Ты можешь хранить массив значений. А для сортировки использовать массив индексов, который ты сортируешь. Операция rotate в этом случае — это просто сдвиг указателя на начало массива (или циклический сдвиг индексов). Это O(1) или O(n) для копирования, но код предельно прост.
Список: Чтобы сделать rotate, тебе нужно менять указатели: head->next становится новым head, а старый head цепляется к tail. В односвязном списке для reverse rotate (rra) нужно найти предпоследний элемент, что требует прохода по всему списку (O(n)), если у тебя нет prev указателя.
Вывод: Если ты используешь односвязный список, операция rra (reverse rotate) будет O(n), потому что тебе придется идти от головы до предпоследнего элемента, чтобы изменить его next на NULL и повесить его в начало. В массиве это можно сделать просто сдвигом или изменением индекса.
Простота односвязного списка:

Односвязный список с tail действительно проще в реализации, чем двусвязный.
Но есть нюанс: reverse rotate (rra).
В двусвязном списке: tail->prev->next = NULL; new_head = tail->prev; tail = new_head; — это O(1).
В односвязном списке: Тебе нужнойти от head до узла перед tail. Это O(n).
Если твой алгоритм сортировки делает много rra, односвязный список будет медленным.
Когда массив лучше?
Если ты реализуешь стек через массив и используешь циклический буфер (или просто сдвиг индексов), то:

swap (меняем arr[0] и arr[1]) — O(1).
push (добавляем в arr[size]) — O(1) (если есть место).
rotate (сдвиг начала массива: start_index = (start_index + 1) % size) — O(1).
reverse rotate (сдвиг конца: start_index = (start_index - 1 + size) % size) — O(1).
В этом случае массив с указанием start_index (начало стека) и size (размер) работает как идеальный стек для Push Swap, где все операции O(1) (без перерасчета памяти).

Итог: Что выбрать?
Ты прав в том, что массив (или массив + индексы) может быть даже удобнее и быстрее для этой конкретной задачи, если реализовать его правильно:

Массив + start_index:

Хранишь значения в массиве int *stack.
Хранишь start_index (куда смотрит "верх" стека в циклическом буфере).
Хранишь size (количество элементов).
sa: меняем stack[start_index] и stack[(start_index+1)%capacity].
ra: start_index = (start_index + 1) % capacity.
rra: start_index = (start_index - 1 + capacity) % capacity.
pa: просто копируем значение.
Односвязный список:

Требует обхода для rra (если нет prev).
Требует выделения памяти на каждый узел (malloc).
Сложнее отлаживать (указатели, утечки).
Мой совет:
Если ты хочешь максимальной производительности и простоты кода для Push Swap, используй массив с циклическим буфером (или просто массив с изменением индекса начала).

Это eliminates необходимость в malloc для каждого элемента.
Все операции (swap, push, rotate, rra) становятся O(1) без проходов по списку.
Код будет короче и понятнее.
